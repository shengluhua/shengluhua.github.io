# 算法与数据结构 · 第 31 课

## Dinic：为什么一次 BFS 可以处理多条最短增广路？

**2026 年 11 月 19 日｜第 5 周 · 第 3 天｜讲授约 17 分钟（自测另计）**

> 昨天的 Edmonds–Karp 每找到一条最短增广路，就重新进行一次 BFS。今天只改变组织方式：**同一轮 BFS 算好层次后，连续沿层次递增的边送流，直到所有这一长度的增广路都被堵住。** 这就是 Dinic 的“层次图 + 阻塞流”。

### 一、学习目标和前提（约 1 分钟）

完成本课应能：①解释层次图与阻塞流，特别分清“堵住路径”和“把所有边填满”；②手工执行 Dinic 的两轮 BFS 与多次 DFS 推流；③写出当前弧优化的正确用法；④证明最短增广路长度逐阶段严格增长；⑤推导一般网络 **O(n²m)** 时间、**O(n+m)** 工作空间。

设有向容量网络有 n=|V| 个顶点、m=|E| 条原始边，s≠t，容量是非负有限数。理论上用精确算术，不要求容量为整数。每条原始边都建立带索引的正反残量弧：正向剩余容量 c−f，反向撤销容量 f。

### 二、BFS 只负责分层，不决定一条特定路径（约 2 分钟）

在当前**残量网络**上，从 s 沿正残量弧运行 BFS，记 level[v] 为到 v 的最少边数（不可达记 −1）。只保留满足以下两个条件的残量弧：

\[
r(u,v)>0,\qquad level[v]=level[u]+1.
\]

得到的子图叫**层次图（level graph）**。每条保留弧都使层数加 1，因此它没有有向环；其中任何 s→t 路径都恰好使用 level[t] 条边，也就是本轮最短增广路。请注意：某条反向残量弧如果恰好指向下一层，也可以出现在层次图中；不能一概禁止反向弧。

下面继续使用上一课的五边网络（括号内是容量），方便比较两种算法。

~~~mermaid
flowchart LR
    S((s)) -->|"3"| A((a))
    S -->|"2"| B((b))
    A -->|"2"| T((t))
    A -->|"1"| B
    B -->|"3"| T
~~~

第一轮 BFS 给出：

\[
level[s]=0,\quad level[a]=level[b]=1,\quad level[t]=2.
\]

因此 s→a、s→b、a→t、b→t 属于本轮层次图，**a→b 不属于**：它连接两个同为第 1 层的点。层次图只包含当前最短路径可能使用的边，并非把原始图永久删边。

### 三、阻塞流：堵住每条当前最短路径（约 2 分钟）

**阻塞流（blocking flow）** 是在当前层次图中增加的一组合法流，使得增加后该层次图中**不再存在从 s 到 t 的正残量路径**。等价地说，原本每一条层次图 s→t 路径都至少有一条边被饱和。

这**不等于每条边都饱和**，也**不等于完整残量网络已经没有更长的增广路径**。阻塞的对象只是当前 BFS 所确定的最短长度。

Edmonds–Karp 的做法是“BFS → 一条路 → BFS”；Dinic 是“BFS → 多次只沿层次递增边 DFS → 阻塞后再 BFS”。一轮 BFS 可以消除多条同长度的增广路。

### 四、完整数值 Trace：两次 BFS，三次推流（约 3 分钟）

<escape>第一阶段：</escape> 层次 0→1→2，有两条长度为 2 的可行路线。

| 阶段内推流 | 本轮允许的路径 | 瓶颈 Δ | 累积流值 |
|---|---|---:|---:|
| 第 1 次 | s→a→t | 2 | 2 |
| 第 2 次 | s→b→t | 2 | 4 |

此时 a→t 和 s→b 都已饱和，原层次图再无 s→t 路径；**第一阶段阻塞流值为 4**。虽然 a→b(1) 仍未使用，但它是同层边，不能在本阶段使用。

<escape>第二阶段：</escape> 重新计算残量：s→a 还剩 1，a→b 还剩 1，b→t 还剩 1。BFS 此时给出：

\[
level[s]=0,\quad level[a]=1,\quad level[b]=2,\quad level[t]=3.
\]

| 阶段内推流 | 新最短路径 | 瓶颈 Δ | 累积流值 |
|---|---|---:|---:|
| 第 3 次 | s→a→b→t | 1 | 5 |

此后源点的两条出边均饱和，第三次 BFS 到不了 t，算法停止。源点侧可达集合为 \(\{s\}\)，其割容量是 3+2=5，与流值相等，因而已经最大。全程 BFS 最短 s→t 边数从 2 变成 3，最后变成不可达。

~~~mermaid
flowchart LR
    P1["第 1 阶段：BFS 距离 2"] --> F1["DFS 送 2 + 2，阻塞当前层次图"]
    F1 --> P2["第 2 阶段：BFS 距离 3"]
    P2 --> F2["DFS 再送 1，阻塞"]
    F2 --> Stop["下一次 BFS：t 不可达；最大流 5"]
~~~

### 五、算法伪代码：当前弧指针避免重复试错（约 3 分钟）

~~~text
DINIC(G,s,t):
    为每条原始边建立独立的 forward/reverse 残量弧配对
    total = 0
    while BFS_LEVEL(s, 仅沿 cap>0 的残量弧):
        if level[t] == -1: break
        ptr[u] = 0 for every u              # 每轮重置
        while (p = DFS_PUSH(s, +INF)) > 0:
            total += p
    return total

DFS_PUSH(u, limit):
    if u == t: return limit
    while ptr[u] < len(adj[u]):
        a = adj[u][ptr[u]]
        v = a.to
        if a.cap > 0 and level[v] == level[u]+1:
            p = DFS_PUSH(v, min(limit, a.cap))
            if p > 0:
                a.cap -= p
                reverse(a).cap += p
                return p                    # 有剩余时，下次可继续尝试此弧
        ptr[u] += 1                         # 当前弧无用，才跳下一条
    return 0
~~~

BFS 需要把全部可达点的层次建好；伪代码里的 BFS_LEVEL 返回层次信息，外层据 level[t] 判断是否继续。只使用正残量弧，避免容量为 0 时无意义递归。

**当前弧（current arc）不变量：** 在同一阶段中，ptr[u] 之前的出弧已经被证明不可能继续产生有效的层次递增推流；它们无需反复扫描。只有尝试失败才前进 ptr[u]，成功推流后保留当前索引，以免错误跳过尚有剩余容量的弧。**下一轮 BFS 必须重置所有指针**，因为层次关系可能改变。

每次沿残量路径推流都保持容量约束和流守恒；正向残量减少、配对反向残量增加，所以允许撤销以前的决策。层次严格递增意味着 DFS 不会在当前层次图中陷入有向环。

### 六、正确性：为什么阶段结束后最短距离严格增大？（约 3 分钟）

首先，在任意一轮 BFS 建好的层次图中，所有可用弧都使旧层数加 1。一次 DFS 推流后，**可能新增正残量的弧**只能是所走层次弧的反向弧；这些新弧从旧的第 i+1 层指回第 i 层，不可能帮助构造更短的正向 s→t 路线。旧有其他残量弧本来就满足 BFS 三角不等式，因而任何顶点的残量最短距离不会下降。

更严格地，假设下一次 BFS 仍找到长度不超过旧的 L=level[t] 的 s→t 路径。它每一步都必须使旧层数增加 1，才能在最多 L 步到达旧第 L 层的 t；因此整条路径只能使用旧层次图里的递增弧。但阻塞流已经使**所有**这样的 s→t 路径至少有一条弧饱和，而新出现的反向弧又是降层弧，不可能补上这条路径。矛盾。

所以每完成一个阻塞流阶段，如果 t 仍可达，就有

\[
\boxed{level_{\mathrm{next}}[t] > level_{\mathrm{old}}[t].}
\]

一条最短简单路径最多有 n−1 条边，因此有效阶段至多 n−1 个。最终 BFS 无法到达 t 时，由上一课最大流–最小割证明，当前流即最大流；Dinic 只是更聪明地组织合法的残量增广，并未改变最大流正确性条件。

### 七、为什么总时间 O(n²m)？（约 2 分钟）

单阶段 BFS 需要 O(n+m)。利用当前弧指针，所有顶点的指针在**同一阶段**合计最多越过 O(m) 条残量弧；每次成功的完整 s→t 推流至少会饱和一条层次弧，因此成功推流次数至多 O(m)，而每次递归路径长度至多 n−1。于是**构造一个阻塞流最坏 O(nm)**，整个算法至多 O(n) 个阶段：

\[
\boxed{T_{\mathrm{Dinic}}=O(n^2m),\qquad S_{\mathrm{extra}}=O(n+m).}
\]

这里假设常规邻接表、当前弧优化，并把初始化与 BFS 的 O(n+m) 成本计入；对通常存在源汇路径的情形，上述界包含这些工作。邻接表残量弧、层次数组、指针和 DFS 栈占 O(n+m) 空间。

对比 Edmonds–Karp 的 O(nm²)：EK 每条最短增广路都重新 BFS；Dinic 在一次 BFS 后处理整个阻塞流。**两个上界并不意味着任何具体输入 Dinic 都严格更快**。非整数容量不破坏组合复杂度证明；浮点实现则必须谨慎处理正残量容差。原图的平行边或相反方向原始边，要分别保存边 ID 和对应的反向残量弧，不能错误合并。

### 八、小结与下一课（约 1 分钟）

\[
\boxed{\text{BFS 分层} \to \text{DFS 求阻塞流}
\to \text{最短增广路长度严格增长}
\to O(n^2m).}
\]

最容易犯的三个错误是：**把阻塞流误解为填满全部边；把层次图当作永久修改原图；成功推流后错误地跳过仍有剩余容量的当前弧。**
