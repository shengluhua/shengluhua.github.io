# 计算机体系结构 · 第21课
## 第3周综合复盘：从错误路径恢复到跨核可见性的四层验证

**2026年11月9日｜第3周第7节·复盘课｜预计18分钟**

前六节课（第15—20课）研究的是同一件事的不同侧面：CPU为获得更高的ILP，允许在分支真实结果未知时继续执行；但**“最终程序算对”不等于“所有内部痕迹消失”，更不等于“跨安全域不可观察任何秘密”**。今天不引入一套全新的防护术语，而要学会把一个CPU方案按四层逐项验收：**功能数据正确 → 架构提交正确 → 微架构保密性 → 系统性能及跨核内存模型**。

本周脉络：第15课讲Squash后Cache痕迹；第16课讲BTB、RSB和Retpoline；第17课讲IBT、Shadow Stack与精确CFI；第18课讲投机窗口和安全检查的位置；第19课讲控制实验、非干扰与反事实性能；第20课讲IBPB、STIBP、SMT和上下文切换。本课把它们串成一个可验证的系统。

## 一、总览：同一个“错误路径”有四种问题（约2分钟）

设B是一条条件分支，真实结果是Not Taken，但前端先预测Taken；较年轻的L沿预测路径执行Load。

~~~mermaid
flowchart TD
    P["B: 预测Taken / 记录GHR与RAT快照"] --> Y["L: 错误路径Rename / ROB与LSQ分配"]
    Y --> M["L可能提前发送Cache请求"]
    P --> R["B执行：真实Not Taken"]
    R --> S["Squash错误路径年轻指令"]
    S --> A["恢复PC、RAT、Free、GHR"]
    A --> C["正确路径按序退休"]
    M -. "微架构效果不必被逐位回滚" .-> O["观察者可能测到延迟差异"]
    C --> V["已提交Store继续经Store Buffer/一致性系统传播"]
~~~

这张图不能被简化为“Squash=什么都没发生”。它包含四个不同的判定：
- **结果**：Load和依赖计算是否使用了正确数据？
- **退休**：错误路径指令能否获得不可撤销的架构效果？答案必须由ROB、LSQ和恢复协议保证。
- **观察**：错路访问留下的Cache/TLB变化是否可被另一安全域区分，并且依赖秘密？
- **可见性**：已经退休的Store，何时能被其他核观察到？这取决于内存模型与一致性传播，不由分支恢复决定。

注意：第四个问题中的“可见”不是第二个问题中的“已提交”，也不是第三个问题中的“侧信道可观察性”。

## 二、第一层：分支Checkpoint要恢复什么？（约3分钟）

假设采用显式物理寄存器重命名。RAT将架构寄存器映射到物理寄存器；Free List保存可再分配的空闲版本；ROB记录程序年龄和退休状态；GHR保存供预测使用的分支历史。

分支B预测时，可按微架构要求记录RAT映射和投机GHR快照。错误路径可能分配新的物理目标寄存器，也可能更新投机历史。B解析错误后，必须使正确路径重新看到合法的源版本和历史。BOOM的设计文档分别说明了Rename快照、Allocation List和投机GHR恢复的作用。[BOOM Rename](https://docs.boom-core.org/en/latest/sections/rename-stage.html) · [BOOM BPD](https://docs.boom-core.org/en/latest/sections/branch-prediction/backing-predictor.html)。

**GHR的精确Trace。** 使用3位GHR，约定最新预测位移入最低位：

\[
H'=((H\ll1)|b)\;\&\;7,\quad b\in\{0,1\}.
\]

预测B之前，\(H=001_2\)。B预测Taken（1），得到 \(011_2\)。错误路径上的分支C又预测Not Taken（0），得到 \(110_2\)。后来B解析为Not Taken（0）。此时**不能直接把当前110当作正确历史**；应恢复B预测前的001，再移入B真实的0，得到 \(010_2\)。C属于被删除的路径，不应继续污染正确路径历史。

**Free List不变量。** 设Live是当前有效映射、未完成消费者或恢复机制仍需引用的物理寄存器集合，则必须有

\[
\boxed{\mathrm{Free}\cap\mathrm{Live}=\varnothing}.
\]

不能在Squash时简单释放“所有曾被碰过的物理寄存器”。被错误路径新分配的版本应按所有权记录撤销；分支之前仍有效的版本必须保留。正常指令退休后才能安全回收相应旧版本（stale pdst）。

**退休前缀不变量。** 已退休的指令在程序顺序上应组成一段合法连续前缀。错误路径即使已执行、已写回，也不能跨过尚未解析的较老分支产生不可撤销的架构提交。

一个边界：ROB能保证架构退休顺序，却不要求Cache行、TLB表项、预测器内部位也在Squash时恢复为先前的逐位状态。

## 三、第二层：LSQ与分支恢复如何交织？（约2分钟）

考虑：

~~~text
S0: STORE [p], 9       # 数据已知，地址稍后才知
L1: r = LOAD [X]       # M[X]初始为4，先投机读4
B2: if (r == 4) goto WrongPath
I3: ...                # 使用r的年轻消费者
~~~

如果后来p解析为X，那么S0是L1较老的同址Store。L1不应永久保留旧值4；它需要从符合字节覆盖条件的较老Store获得应读值，或者等Store数据准备完成。由于B2使用了错误的r，正确性恢复范围还必须包括受影响的分支控制流和年轻消费者。本讲允许一种简单恢复：从违例Load L1开始冲刷全部年轻指令、恢复相应重命名与预测状态，再重取。

**为什么“只修改r”不够？** 因为依赖r计算过的I3和B2可能早就发射，甚至令前端沿错误PC继续工作；必须保证所有可能提交的依赖结果都与重新执行一致。

**为什么这仍不涉及全局可见性？** 同核L1可以从尚未对其他核可见的已知Store数据转发；较老Store是否已经跨核传播，是另一个独立时序问题。

## 四、第三层：架构控制流正确，不等于保密性证明（约3分钟）

第16、17课中的几个结构容易被混为一谈：

| 结构/机制 | 主要职责 | 不能单独保证 |
|---|---|---|
| BTB / 间接目标预测 | 提前猜测间接分支的目标PC | 目标一定属于调用点授权集合 |
| RSB (RAS) | 预测RET的返回PC | 普通栈返回地址未被篡改 |
| CET-IBT / ENDBR | 约束受保护间接CALL/JMP的入口形式 | 精确的调用点允许目标集合 |
| CET Shadow Stack | 对照受保护返回副本校验RET | 没有任何瞬态微架构副作用 |
| Retpoline | 在适用CPU上约束间接分支投机路径 | 无条件消除全部Spectre变种 |

对于某个调用点c，软件希望真实目标 \(T\) 属于集合 \(\mathcal A(c)\)。如果两个函数F和G都标记ENDBR，而业务规则只允许F，那么“G有ENDBR”不代表 \(G\in\mathcal A(c)\)。这是**粗粒度合法入口**与**精确调用授权**之间的差异。

同样，RSB是预测器栈，不是Shadow Stack；RSB预测正确不能替代受保护返回地址比较。即使IBT或Shadow Stack最终触发架构异常，也不能未经验证就声称内部不存在任何瞬态请求。

**保密性检查的数学形式。** 固定公开输入p，只改变受保护位s；令O为威胁模型中攻击者实际能观察的事件或时间分布。理想化非干扰要求：

\[
\boxed{P(O\mid p,s=0)=P(O\mid p,s=1)}.
\]

架构结果相同并不能推出上式成立；反之，观测到一条Cache Line变化，也并不自动证明上式不成立。必须说明秘密如何影响请求、观察者怎样测量、差异是否可重复，并用正控制（可测到已知公开差异）、负控制（不依赖秘密的相同访问）排除混杂因素。

**安全检查位置。** 如果B是合法性检查，敏感请求M必须遵守“检查真正完成先于M发出”的目标约束。把屏障放在检查之前，不自动建立这条关系；将适用的投机屏障放在检查之后、敏感消费之前，或构造经过机器码验证的安全地址依赖，是不同的缓解路径。屏障、范围约束和CFI解决的风险不完全相同。

## 五、系统边界：IBPB、STIBP与SMT（约2分钟）

~~~text
跨时间：
逻辑CPU0   [租户A] -- 切换/适用IBPB -- [租户B]

SMT并发：
物理Core P
  LP0      [租户A ─────────────────]
  LP1      [租户B ─────────────────]
~~~

IBPB主要用于适用条件下的**先后执行预测影响**边界；STIBP主要限制**同物理核心兄弟逻辑线程的并发间接预测影响**。eIBRS提供规定预测模式之间的硬件限制，但不能由此推出所有BHI风险或Cache侧信道都不存在。不同物理核心也可能共享LLC、内存带宽或互连。

VM-exit与普通进程Context Switch不同：进入VMM时不一定发生进程切换。因此，防护应覆盖真实的安全边界，而不是仅依赖某一个调度回调。Linux目前的Spectre说明分别列出IBPB、STIBP、BHI、RSB及相关缓解状态：[Linux Spectre文档](https://docs.kernel.org/admin-guide/hw-vuln/spectre.html)。

实测SMT时必须分开报告**每线程延迟/IPC**和**整核心总吞吐**。两个线程的单独IPC都下降，也有可能让核心合计吞吐上升；反过来，禁用SMT可能降低并发共享风险，但未必消除LLC侧信道，也可能增加排队。

## 六、性能验收：总周期、重叠区间与反事实（约2分钟）

令 \(N\) 为完成同一工作的退休指令数，\(C\) 为总周期，\(f\) 为固定时钟频率：

\[
CPI=C/N,\quad IPC=N/C,\quad T=C/f.
\]

如果防护引入额外的跨域切换代价、屏障或间接分支保护成本，**仅在成本互不重叠且工作量不变**时，才允许把相应独立周期项直接加到基线。

例：某时间线上Branch Recovery占 \([120,144)\) 共24周期，ROB Full占 \([136,156)\) 共20周期。两段重叠8周期：

\[
|A\cup B|=24+20-8=36\ {\rm cycles}.
\]

把两个事件计数相加得到44个“损失周期”，是重复统计；但即使并集是36，也不等于只消除其中一个因素时必然节省36周期。**观察到事件和证明其反事实因果收益是两回事。**

再设两版本固定指令数和频率，A版 \(CPI_A=1.00\)，B版 \(CPI_B=1.15\)。那么B运行时间增加15%，而 \(IPC_B/IPC_A=1/1.15\)，IPC下降约13.04%。两种百分比的分母不同。如果防护改变了指令数，更应报告相同任务的**端到端完成时间**，不能只看IPC。

## 七、重点纠错：SC、TSO与“全局可见” （约2分钟）

再看经典Store Buffering：

~~~text
初始 X=0，Y=0
Core 0                Core 1
Sx: STORE X=1         Sy: STORE Y=1
Ly: r0=LOAD Y         Lx: r1=LOAD X
~~~

为什么SC（顺序一致性）**不允许** \(r_0=r_1=0\)？SC要求一个保留每核程序顺序的全序。若两个Load都读初始0，就需要满足：
\[
S_x<L_y<S_y<L_x<S_x,
\]
产生严格先后环，矛盾。

为什么TSO类Store Buffer模型**可以允许** \((0,0)\)？各核的Store可先进入本核缓冲并按规则推迟传播，同时后续**不同地址**的Load观察到对方尚未传播的旧值。这里不必发生任何分支误预测，也不意味着秘密泄漏。

**特别小心三个“不能等同”：**
1. **Store从ROB按序退休 ≠ Store瞬间对其他核全局可见**；
2. **本核较年轻同址Load可以从较老Store转发 ≠ Store已经向其他核传播**；
3. **Cache一致性保证某地址的合法写入/观察规则 ≠ 内存模型规定所有不同地址操作必须呈SC全序**。

不要把TSO理解为“CPU可任意乱序”。它只在规定关系上允许放松；同核读自己的较老同址Store仍须遵守正确的数据来源和顺序约束。

## 八、第3周复盘结论与下周预告（约1分钟）

面对任何乱序/投机相关设计，按下面的审计顺序：
**(1) 源物理版本和LSQ数据来自哪里？(2) 哪些指令可退休、哪些需要Squash或Replay？(3) 谁能观察什么微架构状态，观察是否依赖秘密？(4) 安全域切换、SMT和Store Buffer如何影响系统级行为？(5) 在同一工作量下，端到端性能是否真的改善？**

如果能独立回答这五问，就不容易把“预测正确率”“安全防护开关”“全局可见”或“IPC上界”误当成最终结论。

# 第21课四级分级测评（满分100分）

**课堂首次发送不公布标准答案或评分参考推导。** Lv1—Lv3可客观判分；Lv4保存完整作答并由人工/自评按Rubric评分，不冒充自动证明。

### Lv1｜架构控制流检查与侧信道结论
**15分｜单选｜预计2分钟**

一条错误预测路径最终被正确Squash；其间一次间接CALL落在带ENDBR的函数入口，RET的Shadow Stack校验也没有出错，但错误路径曾产生Cache请求。此时哪种结论最严谨？

**A.** 既然IBT和Shadow Stack检查通过，这条间接CALL必然属于原调用点的精确业务授权集合。

**B.** 既然最终Squash，所有Cache/TLB和预测器状态必然逐位恢复。

**C.** 架构控制流与提交可能正确，但精确调用授权和秘密相关的微架构观测仍须独立验证。

**D.** 只要Cache请求发生，就已经证明有受保护信息泄漏。

### Lv2｜错误路径GHR恢复与GShare索引
**20分｜数值｜预计4分钟**

教学GShare采用3位GHR，初值101₂，移入新位的规则H'=((H<<1)|b)&7。分支A预测Taken(1)，其错误路径上B再预测Taken(1)、C再预测Not Taken(0)；随后A解析为Not Taken(0)，处理器恢复A预测前的GHR并移入A真实结果。接着在正确路径PC=0x154处预测D，索引i=((PC>>2) XOR GHR)&7。问D的PHT索引（十进制）是多少？只填整数。

先丢弃错误路径B、C的历史，回到A预测前，再移入A的真实0；PC右移2位后只看最低3位。

</details>


### Lv3｜四层验证及内存模型跨机制辨析
**25分｜多选｜预计5分钟**

某乱序CPU支持ROB/LSQ、投机GHR、CET及跨域预测器缓解。以下哪些说法成立？选择所有正确项。

**A.** 若Load投机绕过了较老地址未知的Store，后发现同址违例，必须确保错误Load及受影响消费者不会作为合法结果提交。

**B.** 只恢复RAT便足以在所有情况下保证Free List没有把仍被引用的物理版本重新分配。

**C.** 在允许Store Buffering的TSO模型中，两个核各自Store不同地址再Load对方地址都读到旧0，单凭这个结果不构成Spectre泄漏证据。

**D.** 只在逻辑线程T0上执行IBPB，不自动阻止同物理核心T1持续运行并产生所有形式的共享资源干扰。

**E.** 如果Cache命中率不同，就无需固定公开输入或做负控制，也能证明受保护位被泄漏。

**F.** 两个Stall标记覆盖的周期有重叠时，简单相加会重复统计墙钟覆盖时间；并集长度仍不一定等于优化可节省的因果延迟。

<details><summary>可选提示（不泄露答案）</summary>

分别检查LSQ Replay、物理资源所有权、TSO合法结果、SMT并发、实验控制和Stall重叠。

</details>


### Lv4｜LSQ违例恢复、跨域隔离、CPI与TSO综合设计
**40分｜开放推导｜预计10—12分钟**

综合案例：单核初始R1=9、R2=0、R3=0，RAT分别为P1、P2、P3；空闲物理寄存器P20—P24共5个，按从小到大分配。M[X]=4。S0: STORE [p],R1（Store数据9已知，地址p暂未知，不分配pdst）；L1: R2=LOAD[X]，首次投机读旧4，分配P20、stale=P2；B2: if R2==4 goto W3，错误路径走Taken；W3: R3=R2+1，分配P21、stale=P3。后来p=X，采用“从L1起冲刷所有年轻指令、恢复到L1之前的RAT/Free与正确历史，再重取”的策略；正确Not Taken分支执行C3: R3=R2+R1（重用可用的最小物理寄存器）。全部正确指令最终按序退休。另有两个不互信租户可能同核SMT并发，也可能分时切换。教学性能模型：固定N=800000条退休指令，CPI0=1.20，需保护的跨域切换200次，每次IBPB额外60周期；相关间接分支比例6%，每条因并发隔离额外增加1.25周期；新增周期全部不重叠，频率/指令数不变。
A（16分）：写出首次L1/B2/W3的值及其真正违例来源；写出恢复后L1、B2、C3的正确执行结果、最终RAT和五个时刻Free数量（初始/错误路径重命名后/完成Squash后/正确路径重命名后/正确指令退休后）；指出必须保持的资源与退休不变量。
